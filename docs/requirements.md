# MoonEDIFACT 需求与设计决策记录

> 状态：已决定。2026-10-11 用户授权按 goal.md 实现初验，采用其中推荐方案。初验实现范围和验收记录见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。

## 项目类型

- 主类型：`parser + lib`。
- 附加能力：native `cli`；终验才加入增量输入。
- 目标：核心 native、JavaScript、wasm-gc；CLI native。
- 替代方案：native-only CLI 能更快交付，但降低库复用性；直接业务消息建模增加目录和许可风险。

## 架构和 API 待决定项

1. 是否采用“纯 MoonBit 解析核心 + native CLI”并按 `bytes → syntax → lexer → model → envelope → rules/report → cli` 单向依赖。
2. 公共入口是否以 `Bytes` 和显式资源预算为主；如果选择 `String`，如何避免错误假设 UTF-8。
3. 公开模型是保留源字节范围的通用语法树，还是直接暴露业务消息类型；推荐先采用前者。
4. 诊断是否统一使用稳定代码、严重度和字节位置，默认隐藏字段原值；推荐采用。
5. 规则文件是否仅由用户提供、项目不打包联合国目录；推荐采用，发布前核实第三方材料许可。
6. 目标后端、包名、许可证和 `1.0.0` 公共兼容承诺何时冻结。

## 暂定设计规则

- 模块职责单一，依赖无环；CLI 不复制核心逻辑。
- 不可信输入必须有长度/数量上限和 checked arithmetic；不 panic、不静默丢字段。
- 区分语法、封套、业务规则和未校验状态；未知版本/编码明确拒绝。
- 有效、无效、边界和跨 chunk 变形测试均须可复现；黄金样本记录来源。
- 对外 API 在 `0.x` 保持尽量简洁，`1.0.0` 后通过 SemVer、接口快照和迁移文档维护。

## 实施决策

本次按初验范围实施：Bytes 输入、半开字节范围、通用语法树、稳定诊断、默认脱敏报告、严格资源限额。只支持语法版本 3、UNOA/UNOB 及直接消息；业务规则标记为未检查。沿用 ShiChengxu/MoonEdifact 包名和 Apache-2.0 许可证。0.x API 可演进，初验不扩展为业务目录工具。所有提交留在本地，由用户自行 push；公开仓库、远程 CI、Mooncakes 发布和注册表安装记录在发布清单中。
