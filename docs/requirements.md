# 初验需求与设计决策

状态：已实施。2026-10-11 用户授权按 `goal.md` 完成初验，并要求每个小目标 Git 提交、所有提交先留在本地。此前的候选项按计划推荐方案落地。

| 决策 | 实施结果 |
|---|---|
| 主要目标 | MoonBit 原生 UN/EDIFACT 语法解析、封套检查与可定位诊断 |
| 核心场景/用户 | 数据集成开发者读取离线内存/普通 `.edi` 文件，再交给自身业务逻辑 |
| 项目类型 | parser + lib 为主体，native CLI 调用公共库 |
| 输入与模型 | Bytes、无隐式文本解码、通用 AST、原始半开字节范围 |
| 后端 | 核心 native/JS/wasm-gc；文件 I/O/CLI native |
| 初验边界 | 语法 3、限定 UNOA/UNOB、单交换直接多消息；规则层未检查 |
| 不支持项 | 版本 4、组/连续/交互式、非 ASCII、目录、规则、增量与序列化 |
| 隐私和资源 | 默认无字段值/引用的报告，显式 opt-in、六类正整数预算 |
| 模块/许可证 | 沿用 ShiChengxu/MoonEdifact、0.1.0、Apache-2.0，无外部 Mooncakes 依赖 |
| 开发/验证 | 按小目标提交、三目标门禁、合成语料、五例、CLI 与独立消费验证 |

核心按职责文件组织在一个库包；native 文件适配单独包，以避免平台 I/O 影响跨目标使用。终验扩展及 `1.0.0` 兼容承诺不在本次实施范围。

后续由维护者决定实际公共仓库地址、注册表账号/包名可用性、维护联系人和周期。没有把这些外部状态假定为已经完成。任务及证据见 [IMPLEMENTATION.md](IMPLEMENTATION.md) 和 [INITIAL_ACCEPTANCE.md](INITIAL_ACCEPTANCE.md)。
