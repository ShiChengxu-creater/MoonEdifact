# 0.1.0 职责与边界

输入为完整报文字节。库识别服务字符、检查限定字符范围、扫描 release、构建通用段/数据元/组件，并检查单个交换的直接消息封套。CLI 负责参数、有限额的文件读取和报告展示，调用同一公共解析 API。

| 层 | 通过意味着 | 本版未覆盖 |
|---|---|---|
| syntax | 支持的配置、字节字符、转义、段标识和拆分通过 | 每种业务数据元的类型、长度、语义 |
| envelope | UNB/UNZ 与 UNH/UNT 顺序、必需字段存在、引用/计数一致 | 所有服务字段的完整格式、日期有效性和代码表 |
| rules | 本版恒为 `NotChecked` | ORDERS/INVOIC 目录、伙伴规则、业务必填性和段次序 |

核心由同一包中的 `model.mbt`、`syntax.mbt`、`lexer.mbt`、`api.mbt`、`envelope.mbt`、`report.mbt` 组成，单一公共包便于消费。`cmd/options` 为可移植参数处理，`cmd/nativeio` 隔离 C 文件适配，`cmd/main` 为薄 CLI。核心不调用系统文件、网络或时钟。

源范围为半开字节区间。段范围含终止符；数据元和组件范围排除周围分隔符、保留原始 release 字节；空值的范围允许起止相等。UNA 和段间 CR/LF 不出现在段数组中，Document 范围从 UNB 起到最后一段终止符止。

语法错误或扫描阶段资源错误立即终止，不返回部分 Document。封套失败保留完整已解析 Document；Interchange 中可保留已闭合的消息供诊断，不能作为有效交换使用。缺少 trailer 的未闭合消息不会加入消息数组，因此失败结果的 `message_count` 可能小于 UNH 数量。

独立封套 API 要求调用者保持已解析模型的不变量。公开数组可被调用者修改，修改后不能继续沿用先前的校验结论；若需要重新接收不可信输入，应重新调用 `parse`。

未实现版本 4、重复数据元、功能组、连续交换、交互式封套、非 ASCII 编码转换、增量输入、规则加载和重写。X12、HL7、传输网关、AS2/SFTP、交易伙伴管理与自动回执均不在范围内。

本版有限额的完整输入/AST 模式不承诺常量内存、无分配或特定吞吐量。`0.x` API 可在明确的变更记录中演进，尚未承诺 `1.0.0` 兼容性。
